# Auth circuit test fixtures (#165)

Four `Prover.toml` inputs for `auth_circuit`, regenerated by
`scripts/gen-fixtures.sh` and checked by `scripts/run-fixtures.sh`
(which solves each witness and asserts the expected outcome).

| Fixture | Expected | What it exercises |
| --- | --- | --- |
| `valid.toml` | **pass** | Genuine maker + bridger aggregate over the SettlementAuth message. |
| `single_signer.toml` | **pass** | Degenerate aggregate: one key fills both slots (`pk_agg = 2·pk`, `agg = 2·sig`). Still a valid BLS relation, so the circuit accepts it. |
| `invalid_sig.toml` | **fail** | Bridger signs a different message; the aggregate no longer matches `H(m)`, so the pairing check is unsatisfiable. |
| `wrong_pubkey.toml` | **fail** | Correct aggregate signature but `pk_agg` is a different key. |

"pass" = `nargo execute` solves the witness; "fail" = the in-circuit pairing
assertion rejects it. The generator self-checks each case against noble's own
BLS verify before emitting, so a fixture can never disagree with the reference.
